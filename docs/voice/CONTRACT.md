# Simulated driver voice — contract before implementation

Base: 43f39bd on feature/simulated-driver-voice; own worktree, app 3110 and own database on 15440. Person A's existing text-reply controls stay available. The voice panel is an additive entry in the existing incident controls; no redesign or replacement of the incident engine.

No change to Command, receive_driver_reply, proposal, approval or execution contracts is required. A separate persisted voice_sessions table stores a session UUID, incident/order IDs, immutable source references and missing-information context, simulation timestamp, UTC lifecycle timestamps, provider conversation ID, versioned transcript, status, and reviewed confirmation payload. Transcripts are client-reported and operator-confirmed, not independently verified driver facts. Never store the ElevenLabs key or signed URL. No audio recordings are saved by this application.

New operator-authenticated incident-scoped routes:

- GET /api/incidents/:id/voice: configuration availability and saved session history; never secrets.
- POST /api/incidents/:id/voice with {action:"start"}: require llm waiting incident, a persisted unanswered ask_driver and no reply/proposal/execution/active agent lease. With explicit server-side live enable flag and configured private agent, reserve a session and request one short-lived signed WebSocket URL. Return that URL only to the authorized operator, plus incident-derived dynamic variables and session context. No outbound telephone integration.
- POST with {action:"save",sessionId,version,status,conversationId,transcript}: append/update the bounded transcript and lifecycle using optimistic versioning. Statuses connecting/active/ended/cancelled/error. Final confirmation requires explicit ended, a nonempty driver utterance and matching version. Cancel/error never creates a driver reply. An interrupted capture remains unconfirmed; it may be inspected/cancelled or replaced, never automatically interpreted.
- POST with {action:"confirm",sessionId,version,reply:{terminalEta,safe,blockers,text}}: operator reviews original transcript and explicitly enters/corrects UTC ETA, safety, blockers and reply. Atomically lock the incident then session, call the existing receiveDriverReply validator, append voice-source evidence and an audit event, and persist both. Exact confirmation retries are no-ops; conflicting retries/stale versions fail. No model call or booking action occurs. Resume remains the existing explicit run command, same incident and normal provider adapter.

Provider integration: official @elevenlabs/client Conversation.startSession({signedUrl,connectionType:"websocket",dynamicVariables,...callbacks}); server GET https://api.elevenlabs.io/v1/convai/conversation/get-signed-url with xi-api-key header, include_conversation_id=true. Private agent prompt consumes incident_context, missing_information, source_references and simulation_time. Identify conversation as simulated; collect ETA, safety and blockers only, never approve/book/call external tools. Required client events: user_transcript and agent_response. SDK defaults/headers/identifiers must be checked against installed types. Signed links expire after 15 minutes; session client limit 120 seconds with a matching agent-side maximum duration. No automatic reconnect/retry or new session on failure.

Production voice is disabled by default. Tests inject mocked provider transport/SDK explicitly; production never falls back to a mock. Microphone denied, unsupported browser, connecting, active, ended, cancelled and error are visible. Text input remains available. No paid ElevenLabs or business-model calls are authorized by implementation approval.
